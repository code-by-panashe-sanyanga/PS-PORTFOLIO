Vault Comics

Year 1 · 6G4Z0024 Web Development · individual

1. Purpose and tech stack

Vault Comics is a comic book shop site from my Year 1 Web Development unit. Shoppers can browse a catalogue, add titles to a cart that survives a refresh, walk a demo checkout, and send a contact message. The published GitHub copy is a re-upload of that coursework so it sits on my personal profile with the rest of my work.

Layer Choice Reason
Pages HTML5 (home, catalogue, basket, pay, success, about, contact) Multi-page shop flow rather than a single landing page
Presentation CSS Grid and Flexbox in css/style.css Responsive catalogue and layout without a framework
Behaviour JavaScript in js/script.js Cart, forms, and mobile nav
Persistence browser localStorage Cart items stay after closing the tab
Contact PHP handler plus EmailJS / mailto fallbacks Hosting environments handle mail differently

2. Design

The site is a small multi-page shop. Home highlights featured comics. The catalogue lists the full set. Basket reads and writes the cart in localStorage. Pay and success are a demo checkout path (not live card processing). About and Contact are full pages; the contact form tries PHP first, then other mail options if the host will not send mail.

flowchart LR Home[index.html] --> Catalogue[comics.html] Catalogue -->|add item| Basket[basket.html] Basket --> Pay[pay.html] Pay --> Success[success.html] Home --> About[aboutus.html] Home --> Contact[contactus.html] Contact -->|PHP / EmailJS / mailto| Mail[email] Basket <-->|localStorage| Store[(browser storage)]

3. Features implemented

  • Homepage with featured comics
  • Full catalogue page
  • Working shopping cart that persists across sessions via localStorage
  • Demo checkout and order confirmation pages
  • About and Contact pages
  • Contact form with PHP handler and fallbacks for awkward hosts
  • Responsive layout for phone and desktop

6. Challenges and how they were handled

Challenge Approach
Images not loading Removed a duplicate CSS link pointing at a missing file
Mobile hamburger menu Stopped two JS functions sharing the same name and fighting each other
Contact mail across hosts PHP handler, EmailJS option, and mailto fallback
Cart surviving refresh Serialize cart state to localStorage on every change

7. Testing

  • Add items, refresh, confirm the basket still holds them
  • Remove items and clear the cart
  • Walk pay to success without claiming a real payment went through
  • Resize to phone width: catalogue and nav stay usable
  • Submit contact and confirm at least one delivery path works on the host under test

8. Deployment and links

Static site: open index.html or serve the folder with python -m http.server 8000. Contact mail needs PHP configured on the host, or EmailJS / mailto as fallback. Source is on GitHub as a personal-profile re-upload of the coursework.
