Project notes

NovaBank

Brief

A small online banking app with customer and admin roles. Built to practise transfers, auth, and database transactions properly, the way a real bank would need to handle them.

Features

  • Register and login (bcrypt + JWT); new users get a current account, a savings account, and a debit card
  • Deposit, withdraw, and transfer by account number, with statement filters and CSV export
  • Savings pots with optional targets, round-ups on card payments, and a spending breakdown by category
  • Card freeze/unfreeze, spending limits, and merchant category blocks
  • Session management: see active devices, log out everywhere, review recent login activity
  • Admin panel: customer search, account freeze, transaction audit log, flagged-transaction review

Implementation notes

Money movement uses double-entry bookkeeping: every transfer writes a balanced debit and credit into an immutable ledger table inside one database transaction, so a failure partway through cannot leave one side updated and the other not. Balances are stored as Decimal, never float. Card numbers are masked in every API response, and account and card routes check that the logged-in user actually owns the resource before returning anything. pytest covers the ledger and transfer logic; Docker Compose runs PostgreSQL locally.

ChatWire

Brief

A chat app where the server pushes updates to clients. Built after mostly doing request/response HTTP work, and a chance to focus on auth and permission checks outside of a banking context.

Features

  • Communities, channels, DMs, reactions, stories, friends list, typing, edit/delete
  • Flask-SocketIO for live events; SQLite for accounts, messages, friends, and the feed
  • WebRTC calls (mic, camera, screen share); presence kept in memory
  • Dark/light theme, file attachments, quick switcher; pytest on message handlers and auth

Implementation notes

Channel history is loaded once, then only new events are appended, so switching rooms doesn't replay the same messages. Passwords are hashed with bcrypt; sessions use signed, expiring tokens rather than storing the password client-side. Repeated failed logins trigger a short account lockout, and that same check protects the change-password endpoint so it can't be used to brute-force a password either. The friends-only feed and story views check that the viewer is actually the author or a friend before returning anything, not just when listing the normal feed. Online status is kept in memory because it changes every second and does not need to survive a restart.
