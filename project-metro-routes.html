Metro Network Route Planner

Year 2 · 6G5Z0024 ADS · Assessed Exercise 4

1. Purpose and tech stack

Assessed Exercise 4 models a city metro for a transport authority. Stations hold a name and passenger capacity. Links between stations form a graph. The brief is explicit about representation: the graph must be list based, and Dictionary is not allowed. That forces adjacency lists you control, not a hash map shortcut.

LayerChoiceReason
Language C# console C# (.NET Framework) console harness for a sample metro network
Domain Station Name + PassengerCapacity
Graph List based Graph / GraphNode No Dictionary; explicit nodes, edges, counts
Weights Integer minutes on edges Travel time for metrics and route walking

2. Design

Task A builds the unweighted skeleton: add nodes, add edges, report NumNodes and NumEdges. Task B attaches travel times through AddWeightedEdge, then network metrics: AverageOutbound, AverageTravelTime, and GetAllConnections for a station. Task C adds exploration: BFS or DFS across the network, plus FastestRoute, which starts at a station and always takes the unused outbound edge with the lowest travel time, never revisiting a station, then returns the path taken. 

Program harness
  -> Station records (name + passenger capacity)
  -> Graph<T> adjacency lists (LinkedList of nodes)
       AddNode / AddEdge / NumNodes / NumEdges
       AddWeightedEdge (minutes)
       AverageOutbound, AverageTravelTime, GetAllConnections
       BFS / DFS
       FastestRoute: greedy lowest weight next hop, no revisits

FastestRoute is not a full Dijkstra search over all paths. It is the greedy walk the brief specifies: locally cheapest unused edge at each step. That is an important design distinction when explaining the algorithm in a viva or interview.

3. Features implemented

  • Station model with capacity
  • List based graph: add node, add edge, node and edge counts
  • Weighted edges in minutes
  • Average outbound degree and average travel time
  • Neighbour listing by station id
  • BFS or DFS traversal from the console harness
  • FastestRoute greedy path with no station revisited

6. Challenges and how they were handled

ChallengeApproach
No Dictionary Store nodes and adjacency in lists; look up by id with explicit scans
Weights changing the model AddWeightedEdge path used after Task B
FastestRoute vs true shortest path Implement the brief's greedy rule; do not claim global optimality
Revisit prevention Track visited stations while walking the route

7. Testing

  • NumNodes and NumEdges match manual construction of a small network
  • Weighted edges affect AverageTravelTime as expected
  • GetAllConnections returns only adjacent ids
  • BFS/DFS visit each reachable node once on a simple connected graph
  • FastestRoute never repeats a station and prefers the locally lowest weight edge
  • Disconnected start yields a route that stops when no unused edges remain

8. Deployment and links

Re-upload of the ADS coursework on my personal GitHub. Open ADSPortEx4.sln in Visual Studio (F5 / Ctrl+F5), or build with msbuild ADSPortEx4.sln and run ADSPortEx4\bin\Debug\ADSPortEx4.exe. No web host; the graph ADT and harness are the marked artefact.
