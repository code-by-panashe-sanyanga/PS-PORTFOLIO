Emergency Call Queue

Year 2 · 6G5Z0024 ADS · Assessed Exercise 1

1. Purpose and tech stack

Assessed Exercise 1 asked for a console simulation of an emergency dispatch desk. Calls arrive, sit in a queue, and are handled in order. The hard constraint was architectural: implement the queue myself in C#. Built in Queue<T> was banned. The point of the exercise is to own enqueue, dequeue, capacity, and later a circular buffer, not to hide behind the framework collection.

LayerChoiceReason
Language C# console app C# (.NET Framework) console app with a menu-driven dispatcher
Domain model EmergencyCall CallerName, EmergencyType, SeverityLevel (1 to 5) with validation
Structure Custom EmergencyQueue No framework queue; full control of storage and indices

2. Design

Task A establishes a linear queue ADT: Enqueue, Dequeue, Peek, Count, IsFull, IsEmpty, plus a menu to log calls, dispatch the oldest, and list the waiting set. Properties reject illegal severity values (for example 6 or -1) at the boundary so bad data never enters the structure. 

Dispatcher menu
  -> EmergencyCall (validated fields, IComparable by severity)
  -> EmergencyQueue
       Enqueue / Dequeue / Peek / Count / IsEmpty / IsFull
       PeekHighestSeverity (earliest wins on ties)
       DequeueFirstKCalls
       circular array buffer (front / rear / currentSize, wrap with %)

PeekHighestSeverity scans without dequeue (ties broken by earliest arrival). DequeueFirstKCalls removes the first k calls from the front. Storage is a circular buffer so space at the front of the array is reused after dequeues instead of wasting capacity.

3. Features implemented

  • EmergencyCall with validated severity and typed emergency categories
  • Manual queue: enqueue, dequeue, peek, count, full / empty
  • Menu: add call, dispatch next, list all waiting calls
  • PeekHighestSeverity without mutating order
  • DequeueFirstKCalls for bulk remove from the front
  • Circular buffer accounting across all queue operations

6. Challenges and how they were handled

ChallengeApproach
No framework Queue Own storage, head/tail (later wrap), and capacity checks
Peek highest without breaking FIFO Traverse logically; never dequeue during the scan; earliest wins on ties
Bulk dequeue correctness Auxiliary queue or array so partial failure does not corrupt the primary structure
Circular wrap bugs Step through with the debugger on full, empty, and wrap around cases

7. Testing

  • Enqueue then dequeue restores FIFO order
  • Severity outside 1 to 5 is rejected
  • PeekHighestSeverity returns the earliest of the max severity set
  • Dequeue k removes exactly k items when enough exist
  • After Task C: fill, empty, and wrap around without false IsFull / IsEmpty
  • List view matches internal count

8. Deployment and links

Re-upload of the ADS coursework on my personal GitHub. Open ADS_Assess1.sln in Visual Studio (F5 / Ctrl+F5), or build with msbuild ADS_Assess1.sln and run ADS_Assess1\bin\Debug\ADS_Assess1.exe. There is no web deploy; the artefact is the ADT and menu for marking and portfolio evidence.
