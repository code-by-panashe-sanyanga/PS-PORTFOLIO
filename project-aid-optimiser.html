Aid Distribution Optimiser

Year 2 · 6G5Z0024 ADS · Assessed Task 3

1. Purpose and tech stack

Assessed Task 3 combines three skills the unit treats as one package: argue Big O on real methods, ship a generic QuickSort, then apply a greedy packer to a drone aid problem. Each drone carries at most 75 kg. Items have weight and survival priority. The algorithm must take whole items only, ranked by priority per kilogram, until the next item would break the cap.

LayerChoiceReason
Analysis Line by line Big O on Algorithm1 / Algorithm2 Task A marks need full working and notation, not a guessed label
Sort Generic QuickSort over IComparable CompareTo instead of < / == so ints and strings share one sorter
Domain AidItem + PriorityRatio Priority / Weight drives greedy order
Selection GreedyUtils knapsack style picker 0/1 items, 75 kg hard stop

2. Design

Task A is documentation as engineering: open ComplexityFunctions, derive the cost of each line, and state the overall class. Task B lifts the provided QuickSort skeleton into a generic form demonstrated from the menu on integer and string arrays. Task C introduces AidItem (name, weight 1 to 50, priority 1 to 10, read only PriorityRatio), then greedily selects highest ratio first. The brief allows reusing the generic QuickSort to order items before packing. 

Program menu
  -> Sort integers / strings   (generic QuickSort)
  -> Add AidItem / list items
  -> Run greedy packer
       sort by PriorityRatio desc
       take whole items while weight + next <= 75
       report loadout, total weight, total priority

3. Features implemented

  • Written complexity analysis for the two required algorithms
  • Generic QuickSort via CompareTo for any IComparable element type
  • Menu demos for int and string arrays
  • AidItem with validated weight and priority ranges
  • Greedy loadout builder with 75 kg ceiling and no fractional items
  • Printed selection with totals for weight and priority

6. Challenges and how they were handled

ChallengeApproach
Generic compare without operators Pivot decisions through CompareTo only
Greedy is not globally optimal Accept the brief's ratio heuristic; document totals so markers see the policy
Capacity edge cases Stop when the next whole item would exceed 75 kg; never take a fraction
Analysis marks Per line notation matching the ExampleQuestion format in the template

7. Testing

  • QuickSort: unsorted ints and strings leave a non decreasing CompareTo order
  • AidItem rejects weight or priority outside the brief ranges
  • PriorityRatio equals Priority / Weight for sample items
  • Greedy never exceeds 75 kg
  • Higher ratio items are preferred when both fit
  • Empty list and single oversized item produce a sensible empty or skipped loadout

8. Deployment and links

Console solution in the GitHub Classroom repo. Run locally with Visual Studio or dotnet run. No server deploy; the deliverable is analysis plus working sort and greedy menu paths.
